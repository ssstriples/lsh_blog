# 🤖 AI 기반 명세서 작성 파이프라인

> 아이디어 → 요구조건 명세서 → 상세 기술 명세서 → 블로그 게시글 로 이어지는 자동화 흐름 설계 문서

## 1. 목적

블로그 개발 과정 자체를 "AI로 명세서를 작성하는 방법론"의 실사례로 축적한다.
새 기능/글감이 생기면 아래 2단계 체인을 거쳐 문서를 만들고, 이를 다시 블로그 게시글로 가공한다.

## 2. 파이프라인 단계

```
[아이디어 입력]
     │
     ▼
[1단계: 요구조건 명세서 생성 프롬프트]
  - 목적/배경
  - 사용자 스토리 (누가, 무엇을, 왜)
  - 대략적 기능 목록 (MoSCoW: Must/Should/Could/Won't)
     │
     ▼ (사람 검수 및 수정)
     │
[2단계: 상세 기술 명세서 생성 프롬프트]
  - API 엔드포인트 설계
  - DB 스키마 변경사항
  - 컴포넌트/시퀀스 다이어그램
  - 예외처리 및 보안 고려사항
     │
     ▼ (사람 검수 및 수정)
     │
[3단계: 블로그 게시글 변환]
  - 위 문서를 바탕으로 튜토리얼/회고 형태 게시글 작성
```

## 3. 프롬프트 템플릿 (초안)

### 3-1. 요구조건 명세서 프롬프트

```
다음 아이디어에 대해 요구조건 명세서를 작성해줘:
- 아이디어: {idea}
- 형식: 목적, 사용자 스토리, 기능 목록(MoSCoW), 비기능 요구사항(성능/보안)
```

### 3-2. 상세 기술 명세서 프롬프트

```
아래 요구조건 명세서를 기반으로 상세 기술 명세서를 작성해줘:
{requirements_doc}
- 포함 항목: API 명세(request/response 예시), Prisma 스키마, 프론트 컴포넌트 구조,
  상태관리 방식, 에러 처리, 테스트 케이스
```

## 4. 저장 방식

- `docs/generated/` 하위에 `YYYY-MM-DD_{topic}_requirements.md`, `_tech_spec.md` 형태로 저장
- 최종 승인된 문서는 게시글(Post) 테이블의 원본 컨텐츠로 변환하여 발행

## 5. 향후 확장

- Post 작성 시 관리자 페이지에서 "AI 초안 생성" 버튼 → 위 파이프라인 자동 실행
- 생성된 초안은 TipTap 에디터에 바로 로드하여 사람이 다듬는 구조
