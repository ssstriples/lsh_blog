## 1. 대댓글 트리 — 한 번에 가져와서 조립하기

> 💡 **대댓글(트리 구조)**: 댓글에 답글을, 그 답글에 또 답글을 달 수 있는 구조입니다.
> DB에는 각 댓글이 "내 부모 댓글 id(`parentId`)"만 들고 있습니다. 부모가 없으면 맨 위 댓글이죠.

DB에서 트리를 꺼내는 방법은 여러 가지입니다. Prisma의 `include`로 "댓글 → 답글 → 답글의
답글…"을 중첩해서 가져올 수도 있지만, 이 방법은 **깊이를 미리 정해야** 합니다(3단계까지만
가져오기 등).

블로그 글 하나에 달리는 댓글은 많아야 수백 개입니다. 그래서 더 단순한 방법을 골랐습니다.
**그 글의 댓글을 전부 한 번에 가져온 다음, 서버 메모리에서 트리를 조립**합니다.

```ts
const rows = await prisma.comment.findMany({ where: { postId }, orderBy: { createdAt: "asc" } });

const nodes = new Map(rows.map((row) => [row.id, toNode(row)]));
const roots = [];
for (const node of nodes.values()) {
  const parent = node.parentId ? nodes.get(node.parentId) : undefined;
  if (parent) parent.replies.push(node); // 부모가 있으면 부모의 답글 목록에
  else roots.push(node);                 // 없으면 맨 위 댓글
}
```

DB 쿼리는 딱 1번이고, 깊이 제한도 없습니다. `Map`(id로 바로 찾을 수 있는 사전) 덕분에
부모를 찾는 것도 빠릅니다.

## 2. 지워진 댓글에 답글이 달려 있다면?

댓글은 실제로 지우지 않고 `deletedAt`(삭제 시각)만 기록하는 **소프트 삭제**를 씁니다.
그런데 고민이 하나 생겼습니다.

```
A: 이 코드 왜 안 되죠?        ← 삭제됨
 └ B: 세미콜론 빠졌어요!
```

A를 목록에서 빼버리면 B의 답글이 갈 곳을 잃습니다. 그래서 규칙을 정했습니다.

- 답글이 남아 있는 삭제 댓글 → **"삭제된 댓글입니다"로 자리만 남긴다** (내용과 작성자는 숨김)
- 답글이 없는 삭제 댓글 → 목록에서 아예 뺀다

```ts
function pruneDeleted(nodes) {
  return nodes
    .map((node) => ({ ...node, replies: pruneDeleted(node.replies) })) // 자식부터 정리하고
    .filter((node) => !node.isDeleted || node.replies.length > 0);    // 그다음 나를 판단
}
```

**자식을 먼저 정리한 뒤 부모를 판단**하는 게 포인트입니다. 그래야 B까지 지워졌을 때
"삭제된 댓글입니다" 자리도 같이 사라집니다.

## 3. 게스트 댓글 — 로그인 없이 쓰고, 비밀번호로 지우기

블로그 독자가 댓글 하나 쓰려고 회원가입까지 하진 않습니다. 그래서 로그인하지 않아도
**닉네임 + 간단한 비밀번호**만 적으면 댓글을 쓸 수 있게 했습니다. 비밀번호는 나중에
자기 댓글을 지울 때 씁니다.

### DB에 칸이 없었다

막상 만들려고 보니, 처음 설계한 `Comment` 테이블에는 `guestName`만 있고 **비밀번호를
저장할 칸이 없었습니다.** 그래서 컬럼을 하나 추가했습니다.

```prisma
guestPasswordHash String? // bcrypt 해시로만 저장, API 응답엔 절대 포함하지 않음
```

> 💡 **마이그레이션**: DB 테이블 구조를 바꾸는 변경 기록입니다. 이번엔 실제 클라우드 DB에
> 적용하기 전에 `--create-only` 옵션으로 **어떤 SQL이 실행될지 먼저 확인**했습니다.
> "빈 칸 하나 추가"뿐이라 기존 데이터엔 영향이 없다는 걸 확인하고 적용했습니다.

비밀번호는 원문이 아니라 **bcrypt 해시**(되돌릴 수 없게 뒤섞은 값)로만 저장하고, API 응답
목록에서 이 필드를 아예 빼서 실수로라도 밖으로 나가지 않게 했습니다.

### 회원/게스트를 한 주소에서 나누기

```ts
router.post("/:postId/comments", commentRateLimiter, optionalAuth, createComment);
```

`optionalAuth`는 "로그인 토큰이 있으면 누구인지 확인하고, 없어도 그냥 통과"시키는
미들웨어입니다. 그래서 한 주소로 들어와도 서버가 회원/게스트를 구분할 수 있습니다.

회원 댓글은 한 가지를 더 확인합니다. **지금 이 계정이 정지 상태인지 DB에서 다시 확인**하는
겁니다. 로그인 토큰은 15분 동안 유효하기 때문에, 그 사이에 관리자가 계정을 정지해도
토큰만 보고 판단하면 계속 댓글을 쓸 수 있거든요.

### "내 댓글만 삭제"를 게스트에게도 적용하기

5편에서 만든 소유권 검증 미들웨어 `requireOwnership`을 그대로 재사용했습니다. 이 미들웨어는
"이 댓글의 주인 id"를 받아서 요청한 사람과 비교합니다.

그런데 **게스트 댓글은 주인 id가 비어(null) 있습니다.** 그리고 이 미들웨어는 "주인이 null이면
그런 댓글은 없다(404)"고 처리하도록 만들어져 있었죠. 그러면 관리자조차 게스트 스팸 댓글을
못 지우게 됩니다.

미들웨어를 고치면 게시글 쪽 동작까지 바뀔 수 있어서, 대신 **"주인이 있긴 한데 아무 회원도
아니다"라는 뜻의 특별한 값**을 돌려주게 했습니다.

```ts
const GUEST_OWNER_ID = "__guest__"; // 어떤 회원 id와도 겹칠 수 없는 값
return comment.userId ?? GUEST_OWNER_ID;
```

이러면 일반 회원은 "내 것이 아님(403)", 관리자는 예외로 통과합니다. 게스트 본인은 따로 만든
`POST /api/comments/:id/guest-delete`에 비밀번호를 보내서 지웁니다.

### 비밀번호 맞히기 공격 막기

게스트 비밀번호는 4자리면 되는 "간단 비밀번호"입니다. 누군가 0000부터 9999까지 다 넣어보면
금방 뚫리겠죠. 그래서 **틀린 시도는 15분에 10번까지만** 허용했습니다. 댓글 작성도
**1분에 10번**으로 제한해 도배를 막았습니다.

## 4. XSS 막으려다 `a < b`가 깨진 사건

> 💡 **XSS(크로스 사이트 스크립팅)**: 댓글에 `<script>` 같은 코드를 몰래 넣어서, 다른 사람의
> 브라우저에서 실행되게 만드는 공격입니다.

게시글 본문은 굵게/제목 같은 서식(HTML)이 필요했지만, 댓글은 그냥 글자면 충분합니다. 그래서
**모든 태그를 지우고 순수 텍스트만 저장**하기로 했습니다. 도구는 본문에서도 쓴 DOMPurify.

코드를 쓰기 전에 짧게 실험해봤는데, 문제가 바로 보였습니다.

```js
DOMPurify.sanitize("a < b", { ALLOWED_TAGS: [] });
// → "a &lt; b"   😱
```

DOMPurify는 원래 **"안전한 HTML 문자열"을 만들어주는 도구**라서, 일반 글자 `<`도 HTML 기호
`&lt;`로 바꿔버립니다. 이걸 그대로 저장하면 화면에 `a &lt; b`라고 찍힙니다. 코드 질문이
많은 기술 블로그에서 `<`, `>`, `&&`는 아주 흔한 글자인데 말이죠.

해결은 결과를 문자열이 아니라 **DOM으로 받아서 "글자만" 꺼내는 것**이었습니다.

```ts
const fragment = DOMPurify.sanitize(text, {
  ALLOWED_TAGS: [], ALLOWED_ATTR: [], RETURN_DOM_FRAGMENT: true,
});
return fragment.textContent.trim();
```

| 입력 | 결과 |
|---|---|
| `a < b && c > d` | `a < b && c > d` ✅ |
| `<script>alert(1)</script>hi` | `hi` |
| `<img src=x onerror=alert(1)>pic` | `pic` |

그리고 화면에서는 이 텍스트를 HTML로 해석하지 않고 그냥 글자로 렌더링합니다(React는 기본적으로
글자를 안전하게 이스케이프합니다). 서버에서 한 번, 화면에서 한 번 — **2중으로** 막는 셈입니다.

## 5. 화면 — 본문은 캐시, 댓글은 실시간

8편에서 상세 페이지 본문은 **ISR**(60초 캐시)로 만들었습니다. 그런데 댓글까지 60초 캐시면,
방금 쓴 댓글이 1분 동안 안 보이겠죠. 그래서 댓글 영역만 **브라우저에서 따로** 불러오고,
작성/삭제하면 바로 다시 불러오게 했습니다.

```
게시글 상세 페이지
├── 본문            ← 서버에서 미리 만든 HTML (ISR)
└── CommentSection  ← 브라우저에서 실시간 조회
    ├── CommentForm   (로그인이면 내용만, 비로그인이면 닉네임+비밀번호)
    └── CommentItem   (답글이 있으면 자기 자신을 다시 그림 — 재귀)
```

작은 디테일도 몇 가지 챙겼습니다.

- 글쓴이 본인 댓글엔 **"작성자"**, 게스트 댓글엔 **"비회원"** 배지
- 게스트 댓글 삭제 비밀번호는 `window.prompt`(입력한 글자가 그대로 보임) 대신 비밀번호 입력칸으로
- 로그인 상태를 확인하는 짧은 순간에 게스트 입력칸이 깜빡이지 않도록, 확인이 끝난 뒤에만 표시
- 관리자는 `/admin/comments`에서 전체 댓글을 내용·작성자로 검색하고 강제 삭제

## 6. 트러블슈팅: 껐다고 생각한 서버가 살아 있었다

백엔드를 다시 띄우고 테스트를 돌렸는데, 회원가입이 바로 막혔습니다.

```
signup b: 429 {"success":false,"message":"회원가입 시도가 너무 많습니다. 1시간 후 다시 시도해주세요."}
```

이상했습니다. 가입 횟수 제한은 서버 메모리에 기록되니, **새로 켠 서버라면 0회**여야 하거든요.
로그를 보니 새 서버는 켜지자마자 조용히 꺼져 있었습니다. 포트를 누가 쓰고 있는지 확인해보니…

```bash
netstat -ano | grep -E ":4100 |:3000 " | grep LISTEN
#   TCP    0.0.0.0:4100   ...   LISTENING   9668
```

**지난번(9편) 테스트 때 켰던 서버가 아직 살아 있었습니다.** `npm run dev`를 종료했을 때
바깥 껍데기(npm, nodemon)만 꺼지고, 안에서 실제로 돌던 서버 프로세스는 남아서 포트를 계속
잡고 있었던 거죠. 결국 테스트는 **댓글 기능이 없는 옛날 코드의 서버**에 요청을 보내고 있었고,
가입 횟수도 그 서버에 쌓여 있었습니다.

프로세스의 실행 명령을 확인해 이 프로젝트 서버가 맞는지 본 뒤 종료하니 테스트가 정상적으로
통과했습니다.

> 💡 **교훈**: 테스트 결과가 이상하면 코드를 의심하기 전에, **"내가 지금 어떤 서버에 요청하고
> 있지?"**부터 확인하세요. 서버를 껐다는 건 껍데기만 꺼졌다는 뜻일 수도 있습니다.

## 마무리

이번 편의 핵심을 정리하면,

- 트리는 **한 번에 가져와서 메모리에서 조립** (쿼리 1번, 깊이 제한 없음)
- 지워진 댓글은 **답글이 있을 때만 자리를 남긴다**
- 공용 미들웨어를 고치기보다 **넘겨주는 값을 의미에 맞게** 만든다
- 보안 도구도 **출력 형식을 직접 확인**하고 쓴다

다음 편에서는 **검색과 좋아요**를 만듭니다. 제목과 본문을 검색하는 API, 그리고 로그인
없이도 누를 수 있지만 같은 사람이 여러 번 누를 수는 없는 좋아요 버튼을 다뤄보겠습니다.
