# 기술 블로그를 직접 만들어보자 #7 — 카테고리/태그 API와 '한글 슬러그가 사라지는' 버그

> 게시글을 쓸 때 카테고리를 선택하는 기능은 이미 있었는데, 정작 카테고리 자체를
> 만드는 API가 없었습니다. 이번 편에서는 카테고리/태그 API를 추가하다가 만난
> 재밌는(?) 버그 하나를 소개합니다.

## 이 글에서 다루는 내용

1. 카테고리 API는 왜 "조회는 누구나, 변경은 관리자만"인가요?
2. 버그 발견: 한글 카테고리 이름을 넣었더니 슬러그가 사라졌다
3. 원인과 해결

---

## 1. "조회는 누구나, 변경은 관리자만"

이 블로그는 회원이면 누구나 글을 쓸 수 있지만, **카테고리 체계**(예: "개발",
"일상", "리뷰" 같은 큰 분류)는 사이트 운영자가 관리하도록 정했습니다. 그래서
API를 두 그룹으로 나눴습니다.

```
GET  /api/categories              → 누구나 (글쓰기 화면에서 카테고리 선택 시 필요)
POST/PATCH/DELETE /api/admin/categories/:id  → 관리자만
```

경로 이름만 봐도 "이건 관리자만 건드릴 수 있는 거구나"라는 게 명확하게
드러나서, 나중에 코드를 다시 봐도 헷갈리지 않습니다.

---

## 2. 버그 발견: "개발"이라는 이름을 넣었더니 슬러그가 사라졌다

카테고리 이름으로부터 URL에 쓸 슬러그(예: `"Web Development"` → `"web-development"`)를
자동으로 만들어주는 코드를 짜고 테스트를 해봤습니다.

```bash
curl -X POST /api/admin/categories -d '{"name": "개발"}'
```

그런데 응답을 보니 이랬습니다.

```json
{ "name": "개발", "slug": "" }
```

슬러그가 텅 비어있었습니다! 게다가 카테고리를 하나 더 한글 이름으로 만들려고
하니 "이미 존재하는 슬러그입니다" 에러가 났습니다. 둘 다 빈 문자열이니 서로
충돌한 겁니다.

---

## 3. 원인: `slugify`가 한글을 통째로 지워버린다

슬러그를 만드는 데 쓴 `slugify`라는 라이브러리에는 `strict` 모드라는 옵션이
있습니다. "URL에 안전하지 않은 문자는 다 지워버린다"는 뜻인데, 문제는 이
라이브러리 기준으로 **한글도 "안전하지 않은 문자"에 포함**된다는 겁니다.
영어 알파벳과 숫자, 하이픈만 남기고 나머지는 전부 지워버리기 때문에, 이름이
순수 한글이면 지울 게 다 지워지고 아무것도 안 남는 거죠.

> 비유하자면, "이 상자에는 사과와 바나나만 담으세요"라고 했는데 상자 안에
> 오렌지만 잔뜩 들어있던 상황과 비슷합니다. 규칙대로 사과·바나나가 아닌 건
> 다 빼버리니, 오렌지만 있던 상자는 텅 비어버리는 거죠.

다행히 이 프로젝트에는 이미 참고할 수 있는 코드가 있었습니다. 게시글 **태그**를
만들 때 쓰는 코드는 애초에 `slugify`를 쓰지 않고, 직접 정규식으로 한글을
살려두는 방식을 쓰고 있었습니다.

```ts
// 태그 slug는 이렇게 한글을 그대로 살려서 만들고 있었다
name.toLowerCase().replace(/\s+/g, "-").replace(/[^a-z0-9-가-힣]/g, "")
```

카테고리도 똑같은 방식을 쓰도록 고쳤습니다. 영문 이름은 기존처럼 `slugify`
결과를 쓰고, 결과가 비어있을 때만 한글을 보존하는 방식으로 넘어가게 했습니다.

```ts
function toSlug(value: string): string {
  const slugified = slugify(value, { lower: true, strict: true, trim: true });
  if (slugified) return slugified;

  // 한글 등 slugify가 다 지워버린 경우엔 직접 만든다
  const fallback = value.trim().toLowerCase()
    .replace(/\s+/g, "-")
    .replace(/[^a-z0-9-가-힣]/g, "");

  return fallback || "category"; // 이모지만 입력하는 등 극단적인 경우 대비
}
```

수정 후 다시 테스트해보니 `"여행"`이라는 이름으로 카테고리를 만들었을 때
슬러그도 `"여행"`으로 정상 저장되는 것을 확인했습니다.

## 배운 점

한국어 서비스를 만들 때는 "영어권에서 만들어진 라이브러리가 한글을 어떻게
처리하는지"를 항상 의심해봐야 한다는 걸 다시 한번 느꼈습니다. 다행히 이번엔
프로젝트 안에 이미 비슷한 문제를 해결해둔 코드(태그 slug 생성 로직)가 있어서
금방 참고해 고칠 수 있었습니다.
